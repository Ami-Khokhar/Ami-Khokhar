# Design: Neofetch-style GitHub Profile README for Ami-Khokhar

**Date:** 2026-07-11
**Status:** Approved by user (chat), pending spec review

## Goal

A GitHub profile README in the style of Andrew6rant's: an SVG that shows an
ASCII-art self-portrait on the left and a neofetch-style info panel on the
right, with GitHub stats that refresh automatically every day.

## Decisions made during brainstorming

- **Portrait source:** current GitHub avatar photo, with the busy background
  removed so only face/shoulders convert to ASCII. User previews and approves
  the portrait before it is committed.
- **Automation:** yes — stats auto-update daily via GitHub Actions.
- **Info panel content:** skills & languages only, plus public GitHub stats.
  Explicitly excluded: age/"uptime" counter, employer/role, contact links.
- **Lines-of-code stat:** skipped (requires crawling full commit history);
  stats shown are repos, stars, followers, commits — all cheap API calls.
- **Approach:** write our own small generator (Option A), not a fork of
  Andrew6rant's repo.

## Repository

A new public repo named exactly `Ami-Khokhar` (the magic name that makes
GitHub render its README on the profile page). Built locally at
`Apprentice/Ami-Khokhar/`, pushed via the user's existing `gh` login.

### Files

```
Ami-Khokhar/
├── README.md                  # <picture> element: dark_mode.svg / light_mode.svg
├── dark_mode.svg              # generated
├── light_mode.svg             # generated
├── generate.py                # stats fetch + SVG generation (~150 lines)
├── template.svg               # layout with {PLACEHOLDER} tokens, portrait baked in
├── ascii_portrait.py          # one-time: photo -> ASCII text block
├── requirements.txt           # Pillow (portrait step only); generator is stdlib-only
└── .github/workflows/update.yml
```

## Components

### 1. ASCII portrait (one-time)

Background removal is a one-time local step using the `rembg` tool (falling
back to a manual brightness mask if rembg's output is poor); the cutout is
not committed and rembg is not a repo dependency. `ascii_portrait.py` then
converts the cutout into a ~45x40 character grid: downscale, map cell
brightness to a density ramp (`@ # % * | ! . ` → space). Output is pasted
into `template.svg` as `<text>` lines. Never regenerated by the daily job.

### 2. SVG template and themes

Two SVGs from one template, differing only in a small color map
(dark: #161b22-style background; light: white background). Layout: portrait
left third, info panel right, monospace font. Panel lines:

- `Ami-Khokhar@github` header + separator
- Skills: programming languages, tools/frameworks, spoken languages,
  interests (drafted from user's repos; user corrects wording)
- Stats: Repos {REPOS} | Stars {STARS} | Followers {FOLLOWERS} |
  Commits {COMMITS}
- Footer credit: "layout inspired by Andrew6rant" (removable on request)

`README.md` is a single `<picture>` element with a
`prefers-color-scheme: dark` source and light fallback.

### 3. Generator (`generate.py`)

- Fetches the four stats from the GitHub GraphQL API using the token in
  `GITHUB_TOKEN` env var (Actions default token; locally via `gh auth token`).
- Substitutes `{PLACEHOLDER}` tokens in `template.svg`, applies each theme's
  color map, writes `dark_mode.svg` and `light_mode.svg`.
- **Error handling:** any API failure → exit nonzero, write nothing. The
  profile keeps showing the last good SVGs.

### 4. Automation (`.github/workflows/update.yml`)

- Triggers: daily cron + `workflow_dispatch` (manual).
- Steps: checkout → run `generate.py` → commit & push only if the SVGs
  changed. Uses default `GITHUB_TOKEN`; no secrets to manage.

## Testing / verification

1. Run `generate.py` locally against the real API; open both SVGs in a
   browser to check layout and portrait rendering.
2. User approves the ASCII portrait preview before first push.
3. After first push: confirm the README renders on the profile page in both
   light and dark themes.
4. Trigger the workflow manually once; confirm it commits refreshed SVGs.

## Out of scope

Lines-of-code counter, age/uptime line, employer/contact info, animated
SVGs, contribution-graph widgets.
